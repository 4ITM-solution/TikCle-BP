# BE-20 — 이벤트 윈도우 광고 케이던스 단축 (설계 + 구현)

## 문제 (INSIGHT 2026-07-20, 이퀄베리·메디테라피 실측)
메타 광고 스크랩(Ad Library)은 **수집 시점 활성 광고**만 포착한다. `monitorAdsCron`은 매일 06:00
UTC에 `tracked_brands.cadence_days`(기본 3일) 경과 브랜드만 스크랩 → **스크랩 간격 사이에
시작·종료한 단기 딜 광고가 통째로 누락**(7/16 수집분에 6/20~7/5 종료 광고 0건 실측). 프라임 등
이벤트 전후 분석 자체가 불가.

## 해결 — 이벤트 윈도우 내 케이던스 단축
케이스에 등록된 프로모션 이벤트(`promotion_events`) 윈도우 안에 있으면, 그 케이스의 추적 브랜드는
평소 `cadence_days` 대신 **짧은 이벤트 케이던스**(기본 1일=매일)로 스크랩한다.

- **이벤트 윈도우**: `promotion_events`의 `[start_date − LEAD, end_date + TRAIL]`. LEAD/TRAIL 기본
  7일 — 이벤트 램프업(사전 딜)·윈드다운(종료 직후 잔여 광고)까지 포착. env `BP_EVENT_LEAD_DAYS`/
  `BP_EVENT_TRAIL_DAYS`.
- **유효 케이던스**: 윈도우 내 = `min(cadence_days, BP_EVENT_CADENCE_DAYS(기본 1))`. 윈도우 밖 =
  평소 `cadence_days`. (min이라 평소가 더 짧으면 그대로 존중.)
- **판정 소스**: `tracked_brands.case_id` → `promotion_events.case_id` 조인. is_preset 프리셋
  이벤트(프라임데이 등)도 동일 경로로 자동 커버(등록만 돼 있으면).

## 왜 이 설계
- **스키마 변경 없음**: 기존 `promotion_events`(name·start_date·end_date·is_preset·case_id) +
  `tracked_brands.case_id`만 사용. 마이그레이션 불필요.
- **비용 bounded·opt-in**: 이벤트가 등록된 케이스만, 그 윈도우(≈2주) 동안만 고빈도. 평소는 그대로.
  윈도우당 브랜드 1개 추가 비용 ≈ (14 − 5)회 × 스크랩 단가. 이벤트 미등록 케이스는 영향 0.
- **정직**: 스크랩은 여전히 "그 시점 활성"만 잡지만, 고빈도로 딜 광고의 활성 구간을 반드시 1회+ 스냅.
  완전한 소급 복원은 불가(플랫폼 한계) — 실시간 촘촘 스냅으로 근사.

## 구현
`src/lib/inngest/functions/monitor-ads.ts`:
- `effectiveCadenceDays(brandCadence, inEventWindow)` 순수 함수 — 윈도우 내면 `min(brandCadence,
  EVENT_CADENCE)`.
- `casesInEventWindow(db, caseIds, now)` — `promotion_events`에서 `start_date ≤ today+LEAD AND
  end_date ≥ today−TRAIL`인 case_id 집합 (window: today ∈ [start−LEAD, end+TRAIL] 동치 변형).
  실패 시 빈 집합(폴백 — 이벤트 미반영이어도 평소 케이던스로 정상 동작).
- cron `due` 필터가 브랜드별 유효 케이던스로 판정.

## 검증
tsc + 순수 함수 유닛(윈도우 경계·min 규칙·폴백). 실 크론 발화·고빈도 스크랩 실측은 ORCH(유료 Apify).
