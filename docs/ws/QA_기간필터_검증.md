## 2. 종합 판정

**핵심 메커니즘(서버 액션 → `options.period_scope` 저장 → 라이브 집계 WHERE 재적용)은 정상 동작.** KPI 총량(영상·인플 풀), A섹션 요약 인사이트, E섹션 광고 카드 리스트, 매출 비반영 고지, 해제, 케이스 간 격리까지 — 지시서가 명시한 핵심 경로 5개 채널(TK 영상, TK 인플, Meta 광고, BSR-요약, 클러스터 재집계)의 **총량/카드 리스트 레벨**에서는 전부 정확.

**단, "월별 상세 분포(티어별/시간별 브레이크다운)"를 그리는 하위 컴포넌트 3곳이 필터를 안 받고 있다는 공통 패턴 발견**:
1. A섹션 월간 인플 티어 스택 차트 — `phase3.tier_dist_by_month` 캐시 사용
2. B섹션 티어 분포 막대 — `phase3.tier_distribution` 캐시 사용
3. D섹션 BSR 추이/변곡점 차트 — `BsrSection`에 기간 prop 자체가 안 옴(가장 심각 — 유일하게 원인이 "캐시 사용"이 아니라 "배선 누락")

세 곳 모두 **"총량 요약은 필터링된 라이브 쿼리, 상세 분포는 여전히 캐시/무필터 쿼리"**라는 동일한 아키텍처 갭에서 비롯됨 — BE-15가 "IG/YT 명단" 확장에는 대응했지만 "티어 분포"·"BSR 추이" 두 하위 시각화까지는 배선하지 못한 것으로 판단됨.

## 3. 별도 플래그 (기간 필터와 무관, 참고용)

- **Meta 광고 KPI 캐시 stale**: `ks.phase4a.total_ads=121`인데 원천 실제는 327건 (필터 무관하게 부정확). Terez & Honor(789건 유실, 2026-07-07 규명 완료) 사례와 유사한 "delete-후-reinsert" 또는 "phase 재실행 후 캐시 미갱신" 패턴 의심 — phase4a 재계산 또는 캐시 갱신 필요 여부는 BE 판단.
- **React #418 hydration 에러**: Dalba(US) 케이스 방문 시 발견. 기간 필터 미사용 상태에서 발생해 이 기능과 무관 — FE 별도 조사 권고.

## 4. 권고 (조치는 BE/ORCH 판단, QA는 수정하지 않음)

1. BE-15 후속으로 **A섹션 월간 티어 스택**·**B섹션 티어 분포**에 psStart/psEnd 배선 — `monthlyTierByChannel`/`tierDistByChannel` 계산부에 기간 필터 조건 추가.
2. **D섹션 `BsrSection`에 기간 스코프 prop 추가**(가장 시급 — 유일하게 원인이 단순 배선 누락이라 수정 난이도 낮음). 컴포넌트가 `psStart`/`psEnd`를 받아 자체 쿼리 또는 서버에서 필터링한 `bsrSkus`를 사용하도록 변경.
3. 상단 KPI 스트립 "META 광고"·"총 VIEW" 두 배지가 필터·상관없이 캐시 고정값이라는 점을 사용자에게 알리거나(배너 고지 목록에 추가), phase4a 캐시 자체를 갱신하는 방안 검토.
4. React #418은 별건으로 FE 배차 권고.

## 5. 스크린샷 관련 메모

지시서 산출물 요구사항에 스크린샷이 명시돼 있으나, 세션 중 재적용 시도에서 "적용" 버튼 클릭이 서버 액션을 트리거하지 않는 재현 불가 현상(브라우저 세션 이슈로 추정 — 날짜 입력값은 유지되나 KPI가 갱신 안 됨)이 발생해 재현 스크린샷 확보에 실패함. 단 §1의 모든 판정은 최초 실측 시점(적용 성공 확인된 상태)의 관찰 + SQL 원천 대조 + 코드 확인(파일:라인) 3중 근거로 확정된 것이라 신뢰도에 영향 없음. 필요 시 ORCH가 직접 재현 원하면 별도 요청 바람.
