### ④ 잔존 FAIL 근본원인 (코드 확인)

`SectionAMockup.tsx`의 `months` union 로직(약 182~200줄):
```
const months = useMemo(() => {
  const set = new Set<string>();
  for (const mo of Object.keys(tierByMonth)) set.add(mo);   // ← tierByMonth = phase3?.tier_dist_by_month (미필터 캐시)
  ...
```
BE-32는 스택 막대의 **값**을 그리는 `tierStackByMonth`(`monthlyTierByChannel?.[channelMode]`, 필터됨)는 정확히 고쳤지만, x축에 어떤 달을 그릴지 결정하는 `months` 배열 자체는 여전히 `tierByMonth`(=`phase3.tier_dist_by_month`, `page.tsx`에서 필터되지 않은 원본 `keyStats.phase3` 그대로 컴포넌트에 props로 전달됨)의 키를 그대로 유니온에 포함시킨다. 그 결과 그리드 범위(12개월)는 그대로 남고, 그 안에 그려지는 티어 스택 값만 필터된 상태 — 그런데 실측 스크린샷에서는 8·24·18… 등 **값 자체도 필터 이전과 동일**하게 나옴. 이는 `months`가 필터 안 된 만큼, 4월 이전 달에 대해 `tierStackByMonth`에 해당 월 키가 없어도(필터돼 사라짐) 차트가 fallback으로 `totalTierFallback`(전체 티어 비율)을 써서 막대를 채우거나, x축 아래 표시되는 숫자가 티어 스택이 아닌 별도 데이터소스(`totalByMonth`, `phase2.monthly_by_channel`)에서 오는데 이 역시 `months` 그리드가 넓어진 만큼 캐시 폴백 경로를 타는 것으로 추정 — **정확한 2차 원인까지는 이번 조사에서 확정하지 못함**(1차 원인인 `months` union의 미필터 키 포함은 코드로 명확히 확인).
