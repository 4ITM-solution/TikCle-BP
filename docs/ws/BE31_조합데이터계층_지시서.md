# BE-31 — 조합 데이터 계층 (combo-queries)

## 목적
프로토 v12의 교차 뷰들이 요구하는 조인을 서버 모듈 1개로. 전부 기존 테이블 재조합 — 유료 호출 0.
(유료·신규 판정이 필요한 것들은 별도 배차 진행 중: BE-21 브릿지 · BE-22 키메시지 · BE-29 SKU묶음 · BE-30 원본후보 — 이 모듈은 그것들의 결과를 "있으면 조인, 없으면 공백 계약대로" 소비만 한다)

## 산출물: `src/lib/case-detail/combo-queries.ts`

함수군 (각각 계약표의 해당 행 준수):
1. `narrativePerf(caseId, period)` — 내러티브(메타 클러스터)별 {편수, 측정가능 편수, 반응률(댓글/1만뷰), 샵GMV 합, GPM, 채널별 편수}
   - **반응률 NULL 규칙 (BE-23 선반영)**: likes·comments·shares 동시 NULL 및 IG -1은 분모·분자 제외
   - GMV: 기존 page.tsx `clusterBundle`의 kdMap 로직 추출·재사용 (신규 작성 금지)
2. `creatorProfile(caseId, handle)` — 드로어용: {영상수, 최고뷰, 반응률, 풀 내 백분위(percent_rank 평균뷰), 스파크 편수(is_ad), 메타 광고 매칭(파트너십 라벨 확정분 + BE-30 후보분 구분), 활동 기간, 채널}
3. `eventWindow(caseId, eventId)` — promotion_events 1건 → 전(2주)/중/후 구간별 {시딩 편수·Top영상, 신규 광고 수·주요 훅, 활성 광고 수, BSR 구간 최고}
4. `inflectionTopVideos(caseId, month, sortBy)` — 변곡점 월 게시 영상 Top3, 정렬 조회/댓글/저장 — 6지표 포함
5. `sparkByNarrative(caseId, period)` — 내러티브별 is_ad 비중·편수 (C 광고 집행 콘텐츠 탭)
- 공통: `period-filter.ts`의 psStart/psEnd 준수. 표준 영상 카드 6지표(조회·좋아요·댓글·저장·저장율·댓글율) 형태로 영상 반환.
